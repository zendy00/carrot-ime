# IME 상태 표시기 — 스펙 (Spec / PRD)

## Problem Statement

윈도우 사용자는 지금 자기 입력기(IME)가 **한글**인지 **영문**인지(혹은 일본어·중국어 같은 **기타 IME**인지)를 즉각 알기 어렵다. 그래서 엉뚱한 모드로 한참 타이핑한 뒤에야 "ㅎㅏㄴ글"이나 "korean"처럼 잘못 찍힌 걸 발견하고 지웠다 다시 치는 일이 반복된다. macOS에는 텍스트 커서(캐럿) 옆에 현재 입력 상태를 알려주는 표시기가 있지만, 윈도우에는 이에 정확히 대응하는 무료 도구가 없다. 기존 무료 도구들은 대부분 **마우스 포인터** 옆이나 화면 고정 위치에만 표시할 뿐, 실제로 시선이 가 있는 **텍스트 캐럿** 바로 옆에 상주하며 따라오는 것은 사실상 존재하지 않는다.

## Solution

설치해서 켜두면, 사용자가 글자를 입력하는 **텍스트 캐럿 바로 옆에** 현재 입력 상태를 나타내는 작은 **인디케이터**(macOS 스타일 파란 원형)가 떠서 따라다니는 윈도우 상주 프로그램. 인디케이터는 세 가지 상태를 **텍스트 라벨**로 보여준다 — 한글 입력 중이면 `한`, 영문 입력 중이면 `A`, 일본어·중국어 등 다른 입력기면 해당 언어 글자(`あ`/`中` 등). (트레이 아이콘은 한글을 `가`로 표시) 사용자는 눈을 캐럿에서 떼지 않고 자신이 어떤 모드인지 알 수 있어 잘못된 언어로 입력하는 실수를 없앤다.

> **표시 타이밍 개정(2026-07-20):** 초기에는 "항상 상주·항상 또렷"(grilling Q1)이었으나, 타이핑 중 시야를 가리지 않도록 **입력 중에는 숨기고 약 20초 이상 유휴하면 다시 표시**하도록 변경. 포커스만으로는 뜨지 않으며(유휴 카운트는 포커스 시점부터), 진짜 텍스트 입력 컨트롤에 포커스가 있을 때만 대상이 된다. 표시될 때는 여전히 100% 불투명하다.

## User Stories

1. 한·영을 오가며 타이핑하는 사용자로서, 나는 텍스트 캐럿 바로 옆에서 현재 한/영 상태를 보고 싶다, 그래야 잘못된 언어로 입력하는 실수를 미리 막을 수 있다.
2. 사용자로서, 나는 한/영 키를 눌러 모드를 바꾼 즉시 인디케이터 라벨이 `한`↔`A`로 바뀌는 것을 보고 싶다, 그래야 전환이 실제로 됐는지 확인할 수 있다.
3. 사용자로서, 나는 키보드 레이아웃 전환(Alt+Shift, Win+Space)으로 영어 레이아웃이 됐을 때도 `A`로 표시되길 바란다, 그래야 한글 IME 내부 전환과 레이아웃 전환을 구분하지 않고 "지금 뭐가 찍히는지"만 알 수 있다.
4. 다국어 사용자로서, 나는 일본어·중국어 IME를 쓸 때 그 언어를 나타내는 글자(`[あ]`/`[中]`)를 보고 싶다, 그래야 여러 IME 사이에서 현재 어떤 입력기인지 알 수 있다.
5. 사용자로서, 나는 어떤 언어인지 프로그램이 알아내지 못하는 기타 IME의 경우 최소한 `[IME]`라는 폴백 라벨이라도 보고 싶다, 그래야 "영문/한글이 아닌 무언가"라는 사실은 인지할 수 있다.
6. 사용자로서, 나는 인디케이터가 캐럿 오른쪽에 방금 친 글자를 가리지 않게 살짝 떨어져 뜨길 바란다, 그래야 표시기가 입력을 방해하지 않는다.
7. 사용자로서, 나는 인디케이터가 화면 가장자리 근처에서도 화면 밖으로 잘리지 않고 보이길 바란다, 그래야 어느 위치에서 입력하든 상태를 읽을 수 있다.
8. 사용자로서, 나는 캐럿이 이동하거나 창을 바꿔도 인디케이터가 부드럽게 따라오길 바란다, 그래야 항상 지금 입력 지점 옆에서 상태를 확인할 수 있다.
9. 크롬·일렉트론 앱·게임처럼 캐럿 위치를 알려주지 않는 앱을 쓰는 사용자로서, 나는 그런 앱에서도 인디케이터가 사라지지 않고 화면 고정 위치에 떠서 상태를 알려주길 바란다, 그래야 캐럿을 못 잡는 앱에서도 최소한의 정보는 얻는다.
10. 사용자로서, 나는 텍스트 입력창에 포커스가 없을 때(바탕화면 클릭, 버튼 포커스 등)는 인디케이터가 뜨지 않길 바란다, 그래야 지금 타이핑할 수 없는 상황에서 불필요한 표시로 화면이 어수선해지지 않는다.
11. 사용자로서, 나는 인디케이터가 항상 또렷하게(100% 불투명) 보이길 바란다, 그래야 흐릿해서 놓치는 일 없이 언제든 상태를 확실히 읽는다.
12. 관리자 권한 창(관리자 CMD 등)에서 작업하는 사용자로서, 나는 그 창에서도 인디케이터가 캐럿을 따라오길 바란다, 그래야 권한이 높은 창에서도 동일한 도움을 받는다.
13. 사용자로서, 나는 프로그램이 시스템 트레이에 상주하며 조용히 동작하길 바란다, 그래야 작업 표시줄을 차지하지 않고 백그라운드로 돌아간다.
14. 사용자로서, 나는 트레이 아이콘 메뉴에서 프로그램을 종료할 수 있길 바란다, 그래야 필요할 때 손쉽게 끌 수 있다.
15. 사용자로서, 나는 부팅 시 프로그램이 자동으로 시작되도록 설정에서 켜고 끌 수 있길 바란다, 그래야 매번 수동 실행하지 않아도 된다.
16. 사용자로서, 나는 관리자 권한으로 실행되는데도 자동 시작이 UAC 창 없이 동작하길 바란다, 그래야 부팅마다 승인 클릭을 하지 않아도 된다.
17. 여러 모니터를 쓰는 사용자로서, 나는 어느 모니터에서 입력하든 인디케이터가 올바른 위치·크기로 뜨길 바란다, 그래야 고해상도·배율 차이가 있는 환경에서도 정확히 보인다.
18. 사용자로서, 나는 프로그램을 별도 런타임 설치 없이 실행 파일 하나로 쓰길 바란다, 그래야 설치가 번거롭지 않다.
19. 노트북 사용자로서, 나는 이 상주 프로그램이 배터리·CPU를 거의 쓰지 않길 바란다, 그래야 항상 켜둬도 부담이 없다.
20. 사용자로서, 나는 캐럿이 선택 영역(드래그된 범위)일 때 인디케이터가 입력이 일어나는 끝점 옆에 뜨길 바란다, 그래야 선택 중에도 위치가 자연스럽다.
21. 사용자로서, 나는 인디케이터가 클릭을 가로채지 않고 통과시키길 바란다(클릭 통과), 그래야 표시기 뒤의 내용을 그대로 클릭할 수 있다.

## Implementation Decisions

- **아키텍처: 함수형 코어 / 명령형 셸(functional core, imperative shell).** 모든 결정 로직은 단 하나의 순수 함수 **`Decide(InputSnapshot) → IndicatorView`** 뒤에 모은다. OS와 상호작용하는 모든 부분은 이 seam 바깥의 얇은 어댑터로 둔다.
  - **InputSnapshot** (입력 값 객체): 편집 가능한 포커스 여부, 캐럿 사각형(없을 수 있음), 활성 창 사각형, 키보드 레이아웃 언어 ID, IME 조합 모드, IME 이름/식별자, 대상 화면 경계.
  - **IndicatorView** (출력 값 객체): 표시 여부, 라벨 문자열, 화면 위치.
  - `Decide`가 담당하는 것: 입력 상태 판별(한글/영문/기타 IME), 라벨 선택, 캐럿 기준 위치 계산, 폴백 위치 계산, 표시/숨김 규칙 적용.
- **입력 상태 판별.** 포그라운드 창의 스레드 기준으로 키보드 레이아웃 언어 ID를 확인하고, 한국어 IME이면 조합 모드(한/영)까지 확인해 `한글`/`영문`을 가른다. 한국어가 아닌 다른 IME 언어는 `기타 IME`로 분류한다. (`GetKeyboardLayout` + IME 조합 상태 조회를 P/Invoke로 사용.)
- **라벨 매핑.** 오버레이(캐럿 옆): `한글`→`한`, `영문`→`A`, `기타 IME`→언어별 대표 글자(일본어 `あ`, 중국어 `中` 등), 언어를 특정 못 하면 `IME`. 트레이 아이콘: `한글`→`가`, `영문`→`A`, 기타 IME는 오버레이와 동일.
- **캐럿 위치 획득 — 다단 폴백.** `GetGUIThreadInfo`(네이티브 컨트롤) → **UI Automation** 의 텍스트 선택 경계 → MSAA 캐럿 순으로 시도하고, 모두 실패하면 "캐럿 없음"으로 스냅샷을 만든다.
- **표시 규칙.** 편집 가능한 텍스트 포커스가 있을 때만 인디케이터를 띄운다. 편집 포커스가 있는데 캐럿 사각형을 못 얻으면 화면 고정 위치(기본값: 활성 창 우상단)로 폴백한다. 편집 포커스 자체가 없으면 숨긴다.
- **편집 포커스 판정(엄격).** 진짜 편집 텍스트 컨트롤(UIA ControlType Edit/Document, 읽기 전용 제외)에 포커스가 있을 때만 편집 포커스로 본다. 브라우저는 문서 조상에 TextPattern을 노출해 버튼·링크까지 편집으로 오판되므로, TextPattern 유무가 아니라 컨트롤 타입으로 판정한다.
- **입력 중 숨김(debounce).** 텍스트 필드에 포커스가 생겨도 즉시 뜨지 않고, 약 20초 이상 키 입력이 없어야(유휴) 표시한다. 입력 시작(캐럿 이동)하면 다시 숨긴다. 입력 활동은 별도 키보드 훅 없이, 편집 필드에서 이미 도는 폴링의 캐럿 위치 변화로 판정한다. 캐럿을 못 얻는 폴백 앱에서는 활동을 알 수 없어 이 숨김이 동작하지 않고 계속 표시된다(의도된 한계).
- **위치 계산.** 캐럿의 오른쪽에 글자를 가리지 않도록 오프셋을 두고, 화면 밖으로 나가지 않게 보정한다. **알려진 한계:** 일부 웹 입력창(예: 일부 검색창)은 UIA가 캐럿 대신 입력창 박스 전체를 주는데, 이 경우 "오른쪽"이 박스 오른쪽 끝이 되어 인디케이터가 입력 지점에서 멀어질 수 있다 — 브라우저가 정확한 캐럿을 노출하지 않는 앱에서의 한계.
- **가시성.** 표시될 때는 항상 100% 불투명하게 그린다. (상시 상주는 위 debounce로 대체됨 — 유휴 시 페이드가 아니라 표시, 입력 중엔 숨김.)
- **추적 메커니즘.** 상시 폴링 대신 이벤트 기반(위치·포커스 변화 이벤트를 후킹)으로 스냅샷을 갱신하고, 필요한 경우에만 가벼운 폴링으로 보완해 CPU·배터리 사용을 최소화한다.
- **렌더링.** 레이어드(layered)·클릭 통과·최상단·per-monitor DPI 대응 오버레이 창이 `IndicatorView`가 지시한 위치에 라벨을 그린다.
- **상주·트레이.** 시스템 트레이 아이콘 + 설정/종료 메뉴로 백그라운드 상주한다. 트레이 아이콘에는 현재 입력 상태 글자(한/영/あ 등)를 그려 넣어, 인디케이터가 숨겨져 있어도 상태를 알 수 있게 한다(마지막으로 읽은 상태 기준).
- **설정.** 유휴 표시 시간은 트레이 메뉴의 프리셋(5·10·20·30초·1·3분)으로 사용자가 바꿀 수 있고 재실행해도 유지된다. 기본값 약 20초.
- **권한.** 관리자 권한(`requireAdministrator`)으로 실행한다(ADR-0003). 자동 시작은 레지스트리 Run 키가 아니라 **작업 스케줄러의 "가장 높은 권한으로 실행" 작업**으로 등록해 부팅 시 UAC 없이 상승 실행되게 한다.
- **설정.** 자동 시작 켜기/끄기 토글, 켜기/끄기(일시정지). 불투명도는 100% 고정이라 설정에서 제외.
- **기술 스택·배포.** C#(.NET)로 구현하고(ADR-0002), self-contained 또는 NativeAOT 단일 실행 파일(포터블)로 배포해 별도 런타임 설치가 필요 없게 한다.

## Testing Decisions

- **좋은 테스트의 정의.** 외부에서 관찰 가능한 **행동**만 검증한다 — 즉 `Decide`의 입력(InputSnapshot)과 출력(IndicatorView)을. P/Invoke 호출 방식이나 후킹 세부 같은 구현 내부는 테스트하지 않는다.
- **테스트 대상 모듈.** 유일한 seam인 **결정 코어 `Decide`**. 여기서 우리가 확정한 모든 규칙을 평범한 값으로 검증한다:
  - 상태 판별(오버레이 라벨 기준): (한국어 레이아웃 + 한글 조합) → `한`, (한국어 레이아웃 + 영문 조합) → `A`, (영어 레이아웃) → `A`, (일본어/중국어) → `あ`/`中`, (미상 언어) → `IME`.
  - 라벨: 각 상태에 대한 라벨 문자열.
  - 위치: 캐럿이 있을 때 오른쪽 오프셋, 화면 경계에서의 보정.
  - 폴백: 편집 포커스 있음 + 캐럿 없음 → 활성 창 우상단.
  - 표시/숨김: 편집 포커스 없음 → 숨김; 편집 포커스 있음 → 표시.
- **OS 어댑터의 검증.** 캐럿 로케이터·포커스 워처·IME 리더·오버레이 렌더러는 자동 단위 테스트 대신 **수동 통합 체크리스트**로 검증한다(메모장에서 캐럿 추종, 크롬 입력폼, 캐럿 미노출 앱에서 고정 폴백, 관리자 CMD, 멀티모니터·고DPI, 트레이·자동시작).
- **선행 사례(prior art).** 신규 프로젝트라 기존 테스트는 없다 → 순수 코어용 단위 테스트 프레임워크(xUnit)를 새로 도입한다.

## Out of Scope

- **마우스 포인터 옆 표시** — 기성 무료툴(IMECursor 등)의 영역이며 우리는 캐럿을 따라간다(ADR-0001).
- **유휴 시 페이드/반투명** — 표시될 때는 100% 또렷. (단 "항상 상주"는 입력 중 숨김/약 20초 유휴 표시 debounce로 개정됨 — 위 표시 규칙 참조.)
- **3개 초과 세분 상태** — 한글의 "조합 중/대기" 구분 등은 하지 않는다(한글/영문/기타 3종만).
- **macOS·Linux 지원** — 윈도우 전용.
- **uiAccess 서명 방식** — 관리자 실행으로 대체(ADR-0003).
- **완전한 전(全) 앱 커버리지 보장** — 일부 앱은 캐럿을 노출하지 않으며, 그 경우 고정 위치 폴백으로만 대응한다.
- **인디케이터 색상·폰트 커스터마이즈** — 초기 범위에서 제외(추후 고려 가능).
